# 性能实现与测量

## 复现

```sh
npm run build
npm run test:production
npm run benchmark
```

`tests/e2e/performance.spec.ts` 在真实浏览器中构建 5,000 个元素（四分之一为有文字的便签），建立空间索引，以 RAF 驱动 60 帧平移并统计绘制函数耗时；随后缩放到 6%，让 5,000 个对象全部进入视口，再测量 30 帧远景；活动笔迹包含 5,000 个采样点。存储测试创建约 1.27 MB 文档，提交 25 次单对象日志并重新加载。

这些步骤使用开发服务器载入测试模块，生产启动另外通过 `dist/` 的预览服务器测量。首场景帧指标记录场景交给 Canvas 绘制完成的应用时点；不是 GPU fence 或屏幕实际呈现时点。

## 一次测量记录

Windows Edge 155 headless，DPR 1，1440 × 960。不同运行的负载、浏览器首次字体初始化、存储缓存状态会导致变化。

- 生产构建：主 JS 约 79.8 KB 原始 / 27.1 KB gzip；CSS 18.6 KB 原始 / 4.8 KB gzip；Worker 约 3.0 KB 原始且按需加载。
- 首次生产启动：应用 ready 约 120–127 ms，首场景帧约 143–187 ms（从应用构造开始）。
- 已保存的小画板：应用 ready 约 18–19 ms，首场景帧约 25–33 ms。
- 5,000 元素空间索引：约 6–10 ms。
- 100% 视角：72 个对象可见，P50 约 1.2–1.7 ms，P95 约 1.8–2.1 ms。
- 6% 视角：5,000 个对象可见，P95 约 14–18 ms；远景关闭小字号和阴影。
- 活动 5,000 采样点笔迹：P95 约 0.5–0.7 ms。
- 单对象增量写入：P50 约 0.5–0.7 ms，P95 约 0.7–1.3 ms。
- 大文档完整创建包含 Worker 首次加载和数据库提交，约 70–100 ms；重开约 40–60 ms，重计算不在主线程。

## 局部橡皮更新

局部蒙版只为被擦除对象创建隔离合成，未擦除对象沿用原绘制路径；临时 Canvas 复用，只分配对象在视口内的像素区域。擦痕以对象局部坐标的折线加椭圆半径保存，避免持久化整份位图。笔迹路径缓存按原始采样数组复用，添加蒙版不会重建原始笔迹。

新增基准对 5,000 个对象逐个施加一道局部擦痕，100% 视角下测量 30 帧平移：本机一次 P95 约 **5.8 ms**（视口内约 72 个对象）。同时普通场景 P95 约 1.7 ms、远景约 12.6 ms。该测量不包含 GPU 完成时间。新增 Custom Select 和局部橡皮后，主 JS 约 88.8 KB 原始 / 29.7 KB gzip，CSS 约 5.0 KB gzip，Worker 约 3.3 KB 原始。

最终与构建、生产浏览器测试同时运行时，带擦痕场景 P95 为 15.1 ms，普通场景 2.8 ms、远景 21.3 ms、单对象增量提交 P95 为 1.0 ms；首次生产首场景帧 341 ms、小画板重开首场景帧 48 ms。并发负载明显影响结果，因此保留单独基准和并发验证两组数据，不将最佳数值视为固定延迟保证。

## 几何拆分更新

`tests/e2e/cut-performance.spec.ts` 通过真实 Worker 测量裁切往返时间：本机一次 Worker 首次加载加直线裁切约 18.1 ms，预热后直线裁切 P95 约 0.4 ms；600 × 400 填充矩形经过 8 道竖向和 4 道横向擦痕后得到 45 个独立区域，约 10.1 ms。该计算位于后台，不计作主线程绘制或输入响应时间。

新增模型使用 even-odd 填充环、开放/闭合描边与局部孔洞，曲线受控离散成矢量折线。普通绘制路径不加载差集内核，第一次擦除完成后才加载几何 Worker（约 9.8 KB 原始）；主 JS gzip 约 31.9 KB，存储 Worker 约 4.1 KB 原始。选中柔光使用可复用 alpha silhouette，移动视口时只在变更后重建。

本轮新增工具分类、三种多边形、双向箭头、端点与旋转手柄后，生产主 JS 约 34.3 KB gzip，CSS 约 5.1 KB gzip；存储 Worker 约 4.2 KB、几何 Worker 约 10.4 KB 原始。38 个浏览器场景全部通过，常规 5,000 元素基准的视口绘制 P95 约 1.7 ms，带擦痕约 4.6 ms。

## 轨迹识别更新

轨迹识别只在抬笔后运行，输入先归一化并按弧长重采样为 160 点，再拟合三角形、矩形、椭圆候选，以双向轮廓距离选择视觉上最像的一种。所有有效手势强制图形化，不再保留笔迹。普通笔迹预览不增加拟合开销，不调用远程服务。浏览器基准使用 201 点近圆与 2,001 点椭圆交替运行 40 次；三类候选比较版本本机一次识别耗时 P50 约 **4.6 ms**、P95 约 **6.3 ms**。另以 20,001 点输入测试密集轨迹的结果正确性。软件计时不包含输入设备或屏幕扫描延迟。

圆角手绘矩形容错及初始姿态规范化版本对同一基准：P50 约 **6.8 ms**、P95 约 **8.2–9.5 ms**。矩形额外匹配不同圆角轮廓但输出直角几何，距离计算改用平方距离控制开销。新增旋转后的真实鼠标对正测试覆盖矩形、任意三角形、长轴椭圆，以及撤销、刷新和源文件导入后的角度保存。

斜四边结构优先版本新增直边稳定性与对边方向验证，证据成立后直接生成正交矩形。浏览器 40 次三种倾角偏斜轮廓基准：P50 约 **0.2 ms**、P95 约 **0.5 ms**；未进入此快路径的近圆/椭圆基准 P95 约 **9.3 ms**。本轮构建主 JS gzip 约 **39.4 KB**，仍无生产运行时依赖。

新增独立圆角矩形、强制轨迹图形化和三角形局部顶点后，主 JS 约 **37.8 KB gzip**，CSS 约 **5.2 KB gzip**；存储 Worker 约 4.4 KB、几何 Worker 约 10.5 KB 原始。无生产运行时依赖。

异步裁切先保留手势的即时蒙版提交，再以历史事务标识替换片段；导出和切换画板等待当前几何任务完成。片段排序沿父对象层级使用整数分级键，避免在大时间戳数值上插入浮点小数后丢失层级精度。

## 已建立的回归约束

- 指针移动在第一个 RAF 中执行绘制，避免嵌套两次调度。
- 拖动对象时，背景层不随每个移动帧重绘。
- 元数据修改不会读取 / 重写快照记录。
- 自动保存失败后批次不丢弃，后续编辑与失败批次按原序重试。
- 快照编码期间有新提交时拒绝旧快照，防止删除新日志。
- 多窗口版本冲突时拒绝陈旧提交。
- 文件头版本、长度、CRC32 和数据结构必须有效才能打开。
- 生产 Worker 可以导出 / 导入 512 元素并重新打开，无开发模块依赖。

## 测量口径

Canvas API 的调用可能被浏览器延后或批量提交。用一个同步循环压入大量帧会得到命令队列背压，而不是真实显示帧；基准因此每个 RAF 只绘制一帧。绘制函数时间仍不包括全部 GPU 光栅和屏幕扫描。真实触控笔的采样率、操作系统合成器和显示刷新率也会影响输入延迟。

完整文档编码、源文件导出、选择一万个对象同时缩放、图片解码等操作的成本不同于普通手绘。基准覆盖指定合成场景；没有将 5,000 元素结果外推为所有文档都能稳定达到某个刷新率。
